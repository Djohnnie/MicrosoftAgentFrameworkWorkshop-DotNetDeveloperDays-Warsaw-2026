# Exercise 304 - Terrible Startup Pitch: Concurrent Investors

> **Part:** Part 3, Orchestrating agents and workflows  
> **Focus:** Fan one pitch out to three independent investors, then collect their reviews  
> **History:** Fresh, separate sessions for every agent invocation and every round

## What you'll build

Keep the Founder from [exercise 302](../exercise-302/README.md), but let three
investors review its **exact same pitch concurrently**:

```text
                            +-> HypeInvestor ------+
User theme -> Founder ------+-> BootstrapInvestor -+-> barrier -> CollectReviews -> output
                            +-> DoomsdayInvestor --+
```

| Investor | Persona | What matters |
| --- | --- | --- |
| HypeInvestor | Rocket-launching, unicorn-chasing venture capitalist | Viral growth, giant markets, and outrageous ambition; profit can wait. |
| BootstrapInvestor | Penny-pinching retired accountant | Paying customers, immediate cash flow, tiny costs, and no debt. |
| DoomsdayInvestor | Eccentric prepper investing from a bean-filled bunker | Offline operation, repairability, and usefulness without electricity or internet. |

Each gives one strength, two objections, and a fictional **FUND** or **PASS**
verdict. The personas guide their reasoning; C# does not force a particular
verdict. Criticism stays playful and about the idea.

There are **four agents and four model invocations per completed round**:
one pitch plus three independent reviews. The final collector is ordinary C#,
not a fifth agent. There are no tools, shared chat history, debate turns,
human approvals, voting rules, or revision loops.

## Run it

From the repository root:

```powershell
dotnet run --project .\exercises\exercise-304\StartupPitchConcurrent.csproj
```

Use the **.NET 10 SDK** and the
[Foundry configuration from exercise 001](../exercise-001/README.md#1-set-your-microsoft-foundry-credentials):
`FOUNDRY_ENDPOINT`, `FOUNDRY_API_KEY`, and `FOUNDRY_MODEL_DEPLOYMENT`.
All four agents can share one deployment. No credentials or launch profile are
committed; environment variables are sufficient.

Try `a subscription service for developers who forget to take breaks`.
Blank themes are skipped; EOF or case-insensitive `quit` exits.

## 1. Give each investor an isolated invocation

`PitchAgentExecutor` returns the Founder's nonempty pitch as a string.
`InvestorExecutor` accepts that string, creates a fresh session, and returns
an `InvestorReview(Investor, Text)` record. The investor ID is supplied by C#,
not generated by the model.

The small `Bind` helper registers executor **factories** with stable IDs.
The concurrent environment requires factory-created or explicitly shareable
executors. Factories keep the collector's mutable state local to its run;
declaring that collector shareable would be incorrect.

Each investor receives only the pitch, not the other investors' reviews or
the Founder's system instructions. The common review contract is combined
with a different persona for each agent. `InMemoryChatHistoryProvider` and
`StoredOutputEnabled = false` match the earlier exercises; inference still
sends the messages to Foundry.

## 2. Fan out and wait at a barrier

```csharp
Workflow workflow = new WorkflowBuilder(founderStep)
    .AddFanOutEdge(founderStep, [hypeStep, bootstrapStep, doomsdayStep])
    .AddFanInBarrierEdge([hypeStep, bootstrapStep, doomsdayStep], collectStep)
    .WithOutputFrom(collectStep)
    .Build();
```

`AddFanOutEdge` broadcasts the Founder's returned string to all three
investors. It does not divide the pitch into three pieces or ask a model
which investor to choose.

`AddFanInBarrierEdge` holds their messages until **every source has produced
a result**. It then delivers the individual `InvestorReview` messages to
the collector. It does not automatically turn them into a list or write a
combined review.

`CollectReviewsExecutor` rejects duplicate investor IDs, collects three
reviews, sorts them by investor ID for stable display, and yields one array.
`[YieldsOutput(typeof(InvestorReview[]))]` declares that output type to the runtime.
Only this collector is registered as final workflow output.

## 3. Use the concurrent execution environment

```csharp
await using StreamingRun run =
    await InProcessExecution.Concurrent.RunStreamingAsync(workflow, input);
```

The graph describes independent branches; `InProcessExecution.Concurrent`
explicitly enables concurrent execution. The Founder must finish first,
then the three independent inference requests can overlap. The application
does not manually start three tasks or use three sequential `await` calls.

The event loop prints the Founder's pitch, reports investor completions as
they arrive, and prints all three final reviews once the collector yields.
Completion order is nondeterministic; final display order is deliberately
stable. This is workflow-event streaming, not model-token streaming.

Missing configuration, empty responses, duplicate reviews, workflow errors,
and a run without the complete final result fail explicitly. A failed branch
does not become a successful partial result; no retry or fallback is added.

## Compare with the earlier pitch exercises

| Exercise | Handoff | Model calls per completed round |
| --- | --- | --- |
| 301 | Manual Founder-to-Investor calls | 2 |
| 302 | Sequential workflow edge | 2 |
| 303 | Human-input port between Founder and Investor | 2 |
| 304 | Founder fans out to three investors, then a C# collector | 4 |

Concurrency can reduce the review phase's wall-clock latency compared with
three sequential reviews, but does **not** reduce the number of calls or tokens.
Deployment quotas and throttling still apply. Different personas are not
independent factual evidence and do not guarantee better decisions.

The project pins Agent Framework and Workflows **1.24.0**, OpenAI **2.14.0**,
and the OpenAI adapter **10.11.0**, matching exercise 302.

## Try it

1. Pitch a cloud-only rubber-duck subscription. Compare growth, cash-flow,
   and offline-resilience objections.
2. Pitch a hand-cranked break reminder. Does the prepper's perspective differ?
3. Put breakpoints in `InvestorExecutor.HandleAsync`. Inspect the same pitch
   going to three agents and the distinct sessions created for each.
4. Observe completion messages arriving in varying order. The final reviews
   should still be labelled and sorted, not mixed together.
5. Enter a second theme. The collector and all sessions start fresh.
6. Compare with 302: concurrent reviews are independent work, not a chain in
   which one investor rewrites another investor's answer.
